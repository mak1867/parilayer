# Program walkthrough (for a Solidity developer)

This is a guided tour of the on-chain program in `programs/parilayer`, written for
someone who knows Solidity and the EVM but is new to Solana and Rust. It covers
what each account and instruction does, which test protects which invariant,
and how Solana ideas map onto Solidity ones.

All pool arithmetic lives in a separate, dependency-free crate,
`crates/parilayer-math`. The program calls into it and adds the parts that only make
sense on-chain: accounts, signers, token transfers. If you read one Rust file
first, read `crates/parilayer-math/src/lib.rs`.

## Solana for Solidity developers

| Solidity / EVM | Solana / this program |
| --- | --- |
| A contract owns its storage | A program owns **accounts**. Code and data are separate: `Config` and each `Market` are accounts the program created and owns, like storage slots that each live at their own address. |
| Contract storage is paid once in gas | Each account holds a **rent deposit** in SOL proportional to its size, returned if the account is closed. Whoever creates the account pays it (the oracle pays for markets, a buyer pays for their own share account). |
| `msg.sender` | There is no implicit caller. Every instruction lists its **signers** explicitly. `Signer<'info>` in an accounts struct means "this key must have signed the transaction". |
| `onlyOwner` modifier | An Anchor constraint such as `has_one = admin`: the account passed as `admin` must equal `config.admin`, and it must sign. |
| Contract-owned address (the contract's own balance) | A **PDA** (program-derived address): an address computed from seeds plus the program id, with no private key. Only the program can "sign" for it, by presenting the seeds. The pot vault and treasury vault are token accounts owned by PDAs. |
| `CREATE2` deterministic addresses | Also PDAs. `Market` lives at PDA `["market", market_id]`, so the same Gemini refs can never create a second market. |
| ERC-20 contract | An **SPL token mint**. One shared token program serves every token; a "mint" account holds the supply and decimals. Each outcome of each market is its own mint, so shares move between wallets like any token. |
| ERC-20 balance in a mapping | A **token account**: a separate account per (owner, mint). Wallets usually use their "associated token account", a PDA of the owner and the mint. |
| External call (`token.transferFrom(...)`) | A **CPI** (cross-program invocation): the program calls the token program, for example `token::transfer_checked`. When a PDA is the authority, the program signs the CPI with the PDA's seeds (`CpiContext::new_with_signer`). |
| `require(cond, "msg")` | `require!(cond, ErrorCode::X)`. The whole transaction reverts, as on the EVM. |
| Events (`emit Transfer(...)`) | `emit!(BuyEvent { ... })` writes the event into the transaction logs; the relayer's indexer decodes them. |
| ABI | The **IDL** (`packages/sdk/src/idl/parilayer.json`), generated by Anchor from the Rust code. |
| Function arguments only | Arguments **plus every account the instruction will read or write**, listed up front in an accounts struct (`#[derive(Accounts)]`). Solana uses this list to run non-overlapping transactions in parallel. |

One more difference: there is no `uint256`. Amounts are `u64` with 6 decimals
(1 USDC = 1 share = 1,000,000 base units), and intermediate math uses `u128`.

## The accounts

| Account | Address (PDA seeds) | What it holds | Solidity analogy |
| --- | --- | --- | --- |
| `Config` | `["config"]` | admin, oracle (the relayer's key), USDC mint, buy fee (`pool_fee_bps`, default 1%), sell fee (`sell_fee_bps`, default 2%), running totals used to check the treasury | Global state variables |
| Treasury vault | `["fees"]` | USDC token account owned by the Config PDA. Receives every buy fee and the seed shares' payouts, and pays every seed | The contract's own token balance |
| `Market` | `["market", market_id]` | kind, Gemini refs, number of outcomes `n`, share counts `q[32]`, `pot`, status (Open, Halted, Resolved, Voided), winner, payout per share, void prices, `burned[32]` | One struct in a `mapping(bytes32 => Market)` |
| Outcome mint `i` | `["mint", market, i]` | An SPL mint with 6 decimals; its mint authority is the Market PDA | One ERC-20 per outcome |
| Pot vault | `["vault", market]` | USDC token account owned by the Market PDA. Holds the pot | Escrow balance |
| Seed shares `i` | `["seed_shares", market, i]` | The treasury's seed shares of outcome i, owned by the Config PDA | Shares held by the contract itself |

`market_id` is the SHA-256 of the market's Gemini refs, sorted and joined with
`|`, computed by the relayer.

## The instructions

Each handler starts with a plain-English comment saying what it checks, what it
moves and which formula or invariant it implements. In short:

| Instruction | Who signs | Checks | Moves | File |
| --- | --- | --- | --- | --- |
| `initialize` | admin | USDC has 6 decimals; fees ≤ 10% | nothing; creates Config and the treasury vault | `instructions/admin.rs` |
| `update_config` | admin | signer is the admin; fees ≤ 10% | nothing | `instructions/admin.rs` |
| `create_market` | oracle | outcome count and refs fit the kind; probabilities valid; treasury covers the seed | seed USDC: treasury → pot | `instructions/market.rs` |
| `init_outcome_mint(i)` | oracle | outcome exists | mints the seed shares qᵢ to the treasury | `instructions/market.rs` |
| `buy(outcome, usdc_in, min_shares_out)` | buyer | Open; all mints exist; enough shares out | fee → treasury; rest → pot; mints Δ shares | `instructions/buy.rs` |
| `sell(outcome, shares, min_usdc_out)` | holder | Open; seller owns the shares; not below the seed; enough USDC out | burns shares; pays R minus 2% from the pot; the 2% stays in the pot | `instructions/sell.rs` |
| `halt` / `unhalt` | oracle | not settled; current status | nothing | `instructions/market.rs` |
| `resolve(winner)` | oracle | not settled; winner exists; invariant 4 | nothing; fixes the payout per share | `instructions/market.rs` |
| `void` | oracle | not settled | nothing; fixes each outcome's void price | `instructions/market.rs` |
| `redeem(outcome, amount)` | holder | settled; winning outcome (or void) | burns shares; pays from the pot | `instructions/redeem.rs` |
| `redeem_seed(outcome)` | anyone | settled | burns the treasury's seed shares; pays the treasury | `instructions/redeem.rs` |
| `sweep_dust` | admin | settled; all claims paid or 30 days passed | what is left in the pot → treasury | `instructions/redeem.rs` |

Only `sell`, `redeem`, `redeem_seed` and `sweep_dust` can move USDC out of a pot, and each of
them signs as the Market PDA.

## The math, in one place

With qᵢ the shares of outcome i outstanding (seed included), N = ‖q‖ = √(Σ qⱼ²)
and M the pot:

- Cost function: C(q) = N. Price of outcome i: pᵢ = qᵢ / N, at most 1 USDC.
- Implied probability: πᵢ = qᵢ² / N², the value of i's shares divided by the pot.
- Buy with X USDC after the fee: Δ = √((N + X)² − (N² − qᵢ²)) − qᵢ.
- Sell s shares: R = N − √(N² − qᵢ² + (qᵢ − s)²), before the 2% fee.
- Payout per winning share: M / q_winner ≥ N / q_winner ≥ 1.
- Seeding at Gemini's πᵢ with S USDC: qᵢ = S·√πᵢ, which costs exactly S.

Rounding always goes against the trader: shares minted round down, refunds
round down, fees round up, payouts round down. Square roots are integer Newton
iterations on `u128`, taken with extra fractional bits where precision matters.
That is what keeps invariant 1 true after every instruction.

## The invariants and the tests that protect them

| Invariant | Meaning | Checked on-chain in | Protected by tests |
| --- | --- | --- | --- |
| 1. M ≥ C(q) ≥ qᵢ | The pot can always pay at least 1 USDC per winning share | `Pool::check` inside every buy and sell (`parilayer-math`) | `invariants_hold_after_1000_random_buys`, `invariants_hold_after_1000_random_buys_and_sells` (math, property tests); `random_buys_keep_invariants_on_chain`, `random_buys_and_sells_keep_invariants_on_chain` (LiteSVM) |
| 2. Pot vault = M; treasury = fees + seed payouts − seeds | Every recorded dollar is really in the vault | after the transfers in `create_market`, `buy`, `sell`, `redeem` | `Env::assert_invariants` in every integration test |
| 3. Mint supply + burned = qᵢ | No share exists that the math does not know about | after every mint or burn | `Env::assert_invariants`; the random-trade tests |
| 4. payout_per_share × q_winner ≤ M | Resolution never promises more than the pot | `resolve` | `create_buy_resolve_redeem`; the payout checks at the end of the property tests |

Other properties from the spec and where they are tested:

| Property | Tests |
| --- | --- |
| The closed-form Δ matches the integral of the price | `closed_form_matches_numeric_integration` |
| Seeding reproduces Gemini's probabilities within 0.1 points | `seeding_reproduces_probabilities` |
| Rounding never favours the trader | `shares_minted_round_down_exactly`, `fee_rounds_up_and_is_taken_first`, `refund_rounds_down` |
| A winning share pays at least 1 USDC, for every possible winner | the payout loops in both 1,000-trade property tests; `small_buy_floor_return` |
| Void prices fit in the pot | `void_path`; the void checks in the property tests |
| Buy then sell costs exactly the two fees (within 1 base unit) | `buy_then_sell_costs_exactly_the_two_fees` (math), `buy_then_sell_round_trip_costs_the_two_fees` (LiteSVM) |
| Sells rejected when halted, resolved, from the treasury, below the seed, under `min_usdc_out` | `rejects_bad_sells` (math), `sell_rejections` (LiteSVM) |
| Only the oracle can resolve, void or halt | `only_the_oracle_can_resolve_void_or_halt` |
| `min_shares_out` and halts | `min_shares_out_and_halt` |
| A 32-outcome market can be fully created | `thirty_two_outcome_market`, `extreme_seed_thirty_two_outcomes` |

The TypeScript port of the math in `packages/sdk/src/math.ts` is checked bit for
bit against golden vectors that the Rust crate generates
(`cargo run -p parilayer-math --example vectors`), and CI fails if they drift.

## One buy, step by step

What happens when a wallet buys 100 USDC of outcome 1:

1. The frontend quotes the buy with the TypeScript math and sets
   `min_shares_out` from the slippage setting.
2. It sends one transaction with two instructions: create the buyer's share
   account if needed (associated token program), then `buy`.
3. Anchor loads and checks every account in the `Buy` struct: the Config and
   Market PDAs match their seeds, the outcome mint is `["mint", market, 1]`, the
   buyer's USDC account belongs to the buyer, the vaults are the right PDAs.
4. `handle_buy` checks the status, runs `pool.buy` (fee off the top, Δ from the
   closed form, invariant 1), and checks the slippage limit.
5. Three CPIs into the token program: fee → treasury, net → pot (both signed by
   the buyer), and `mint_to` the buyer (signed by the Market PDA's seeds).
6. The new `q` and `pot` are saved, invariants 2 and 3 are checked against the
   real token balances, and a `BuyEvent` is emitted for the indexer.

If any step fails, the whole transaction reverts and nothing moves.

## Running it

```sh
anchor build                    # compile the program (target/deploy/parilayer.so) and the IDL
cargo test -p parilayer-math         # the math and its property tests
cargo test -p parilayer              # the LiteSVM integration tests (needs anchor build first)
```

LiteSVM runs the compiled program in-process, so the integration tests need no
validator and finish in seconds.
